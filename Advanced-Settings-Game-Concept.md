# Advanced Settings

## Game concept and design direction

**Concept consolidated: October 19, 2026**

Advanced Settings is a game played entirely through menus, set inside a simulated work computer. The player pretends to develop software: starting jobs, watching processes, configuring tools, learning languages, installing plugins, releasing programs, and eventually coordinating AI help across multiple projects.

It combines idle and incremental progression with active management, skill trees, deep interface exploration, and discoverable storylines. The central pleasure is making a development setup more capable while discovering that its menus contain far more than they initially reveal.

This document captures the direction established in the conversation. Specific menu paths, incidents, headlines, and dialogue below are illustrative examples, not a finalized content list. Unresolved choices are collected at the end.

## 1. Core identity

- **Title:** Advanced Settings.
- **Format:** All gameplay takes place through menus, panels, tabs, settings, queues, reports, notifications, and other software interfaces.
- **Premise:** You are an employee developing software on a company computer.
- **Progression:** Expand from a small development setup into multiple programs, languages, plugins, automation tools, and AI-assisted operations.
- **Exploration:** Find secret menus through long navigation paths, experimentation, unusual operating conditions, and informed guessing.
- **Stories:** Discover the previous employee's notes, oppose a hacker, pursue promotions, and follow a duck whose plausible antics receive absurd media coverage.

The concept grew from the enjoyment of menus and skill trees. Exploring and configuring the interface must be a substantial part of the game itself.

## 2. Player experience

The player should regularly feel:

- “I made this system run better.”
- “That unlock gives me something new to manage.”
- “I wonder what happens if I change these settings together.”
- “Wait—how did I get into this menu?”
- “This tiny clue suggests there is another whole system somewhere.”

There is always a visible development goal to pursue, alongside less obvious discoveries. Players can enjoy optimization, collecting capabilities, following stories, or searching for obscure branches.

## 3. Core gameplay loop

1. Choose a project and its next features.
2. Configure development tasks and start work.
3. Monitor progress while managing other jobs.
4. Run tests, inspect results, and resolve bugs.
5. Release or update the software.
6. Earn rewards and unlock capabilities.
7. Reinvest in skills, tools, hardware, plugins, and additional projects.
8. Investigate new menus, clues, and unusual behavior as they appear.

The basic development cycle is **choose features → write → test → debug → release → reinvest**.

The opening is small: a basic editor, one project, and few available actions. Progress gradually reveals a much larger desktop and development ecosystem.

## 4. Idle processes and active management

The game borrows the satisfaction of idle clickers: start something, watch it progress, collect an outcome, and improve the process. Several activities can operate together, creating choices about attention and resource allocation.

| Process behavior | Software-themed application |
| --- | --- |
| Continuous production | Ongoing development progress or background research |
| Batch job | Build, test run, or task that finishes and needs collecting or restarting |
| Conversion | Turn available resources or intermediate work into something more useful |
| Monitoring | Observe a process, collect diagnostics, and discover information |
| Experiment | Run a configuration whose full outcome is initially unknown |
| Scheduling | Automate tasks the player has already learned to manage |

While one project builds, the player might research a language, configure an extension, maintain an older program, or investigate a suspicious log entry.

Processes should interact. Pausing a job, changing its output, combining tools, or inspecting it in a particular state can produce new results or reveal secrets. The exact resource model and timing remain undecided.

## 5. Simulated software development

Actual programming knowledge is not required. The player makes understandable choices through menus, while the game represents the imagined coding work.

Examples include choosing to add search, prioritize development speed, improve performance, run additional tests, or assign debugging work. These choices affect progress and outcomes without requiring the player to type real source code.

Releases can earn users, money, and experience. Those are the proposed reward categories; their exact roles and balance are still open.

## 6. Languages, tools, and expanding capabilities

Unlocking a language should introduce useful possibilities rather than merely replace an earlier language with a larger speed multiplier.

| Capability | Proposed gameplay role |
| --- | --- |
| Scripting | Small utilities and automation of repetitive work |
| Web development | Websites, services, traffic, and server management |
| Systems programming | More involved development, optimization, and deeper system access |
| Databases | Store information, connect programs, and investigate accumulated data |
| Plugin development | Extend the editor and eventually create extensions |
| AI assistance | Delegate work, generate alternatives, and coordinate more projects |

Whether languages use real or fictional names has not been decided.

Players eventually expand beyond their first application. Their workspace can contain several programs, development tools, and supporting systems, each with its own menus and activities.

## 7. Skills and personal specialization

Two progression structures overlap:

1. **Visible progression:** Skill trees and explicit unlocks for languages, development skills, tools, hardware, AI, and project types.
2. **Hidden progression:** Undocumented tools, buried settings, unusual interactions, secret programs, and concealed menu branches.

The development environment becomes the player's build. Possible approaches include automating many small utilities, concentrating on one large application, or assembling an elaborate plugin ecosystem.

Unlocks can be purchased, earned through development milestones, discovered through experimentation, or found by navigating the interface. Some hidden branches have been accessible all along.

## 8. Plugins, settings, and automation

Plugins and settings are meaningful gameplay systems. Installing or configuring a tool can change available actions, improve workflows, connect existing systems, or expose new interface branches.

Some interactions are obvious and documented. Others become clues or discoveries. Compatibility options, legacy modes, dependency inspectors, diagnostics, and experimental settings provide believable places to hide content.

Automation develops alongside player understanding. Schedulers and scripts take over familiar tasks, freeing attention for new projects, optimization, and exploration.

Convenience upgrades should feel rewarding while the basic interface remains pleasant to use.

## 9. AI assistance

AI is an unlockable part of the simulated development environment. The progression discussed includes:

- Autocomplete that accelerates current work.
- An assistant that handles assigned tasks.
- Agents that work across separate projects.
- Local models with hardware requirements and distinct capabilities.
- Tools the player develops to improve their own AI-assisted workflow.

Assignments can include debugging, research, maintenance, or investigating unfamiliar tools. AI should create allocation and configuration choices rather than function solely as a universal speed upgrade.

These are in-game systems; no requirement for real external AI services was established.

## 10. Secret menus and discovery

Deep, obscure menus are a defining feature. Some should take considerable guessing and long navigation paths to find.

### Discovery methods

- Follow a deeply nested route through ordinary settings.
- Run particular processes together.
- Inspect a system while it is paused, offline, full, or in another unusual state.
- Combine specific plugins or configurations.
- Return to an older project after gaining a new capability.
- Notice an inconsistency in a tooltip, log, release note, or list of options.

Some secrets combine navigation with operational conditions: the player can reach a panel at any time, but its unusual content appears only while a particular experiment runs.

### Example discovery

**Editor → Plugins → Installed → Theme Engine → Compatibility → Legacy Themes → Import → Supported Formats**

One listed format is **Workspace**. Why would a theme importer accept a whole workspace? Investigating could reveal an abandoned development environment and an otherwise unavailable language.

Another clue might say a tool monitors “all four channels” when only three channels are visible.

### Discovery principles

- Encourage theories and experimentation, while preserving genuinely obscure secrets.
- Use small clues so much of the guessing can become informed guessing.
- Let discoveries reveal meaningful functionality or story content.
- Keep discovered locations accessible through bookmarks, pinned controls, or a recorded directory.
- Make finding a long path satisfying without requiring players to repeat it continually.

## 11. Narrative structure

Four storylines share the same computer. Each has a recognizable way of appearing, a discoverable entrance, optional deeper branches, and a satisfying resolution.

| Story | Main delivery channels | Player involvement |
| --- | --- | --- |
| Previous employee | Old files, comments, saved settings, abandoned plugins | Reconstruct their experience and investigate the company |
| Hacker | Alerts, altered configurations, suspicious processes | Detect interference, defend systems, and trace intrusions |
| Promotions | Email, reviews, company dashboards, assignments | Build a career and manage competing expectations |
| Duck | News, incident reports, camera logs, office messages | Follow exaggerated coverage and uncover plausible explanations |

Players can pursue the stories at different depths. The stories occasionally connect, while retaining their individual identities.

## 12. Story: the previous employee

The person who previously used the computer left notes about the company. They are weird, funny, useful, petty, and sometimes sinister.

At first, the player cannot reliably distinguish a joke from a warning. Helpful shortcuts build trust; ridiculous detours complicate that trust; genuinely unsettling discoveries deepen the mystery.

Illustrative notes:

> “The build server stops responding at 4:17 every Thursday. Management calls this scheduled maintenance. It is Greg's space heater.”

> “If you find a project with your name on it, check the creation date before opening it.”

New tools reveal previously inaccessible evidence. A database unlock might make an old attachment readable. A compatibility plugin might expose comments hidden by the current editor.

The notes are an existing trail uncovered over time. The previous employee's identity, fate, and the company's underlying secrets remain to be written.

## 13. Story: the hacker

A hacker actively interferes with the player's systems. The player must investigate and work against them through the game's menus.

Early signs can include renamed files, unexpected logins, changed settings, or an unfamiliar installed plugin. Later interference can affect builds, divert resources, or present a malicious tool as a convenient repair.

Proposed counterplay includes:

- Inspecting logs and comparing configurations.
- Quarantining suspicious plugins.
- Patching vulnerabilities and isolating programs.
- Monitoring access and preparing decoy projects.
- Choosing whether to stop suspicious activity immediately or observe it for information.

Established defenses automate familiar threats. New incidents provide fresh problems rather than endless repetitions of the same interruption.

The hacker can cause setbacks, but routinely destroying hours of progress would undermine the intended experience. Their identity, motive, and final confrontation remain undecided.

## 14. Story: promotions and career

The career storyline supplies clear progression beneath the optional mysteries.

The player starts with limited permissions and small assignments. Promotions expand access to tools, projects, staff, budgets, and company systems.

Different people value different outcomes:

- Managers want releases.
- Coworkers appreciate reliable internal tools.
- Executives reward impressive metrics.
- Customers want working software.

These goals sometimes align and sometimes conflict. Suggested career directions include technical specialist, manager, and the person who quietly automates a large part of the company.

Career choices can open different menus and perspectives on other stories. Exact ranks, promotion conditions, and branching outcomes remain open.

## 15. Story: the duck

A duck does odd things that attract increasingly exaggerated media attention. Its behavior remains explainable without strained reasoning.

The humor comes from the distance between the reported story and the plausible event. The duck remains an actual duck with ordinary motivations such as food, warmth, habit, and shelter.

| Illustrative headline | Plausible explanation |
| --- | --- |
| DUCK REFUSES TO LEAVE CORPORATE HEADQUARTERS | People feed it beside a warm exhaust vent |
| MYSTERY DUCK PREDICTS COMPANY LAYOFFS | It approaches employees carrying cardboard boxes, some of which contain snacks |
| DUCK BREACHES HIGH-SECURITY FACILITY | A motion sensor opens an automatic door |
| LOCAL DUCK APPARENTLY APPOINTED TO BOARD | A joke directory entry syncs to the public website |

Players uncover explanations through facilities settings, cafeteria orders, support tickets, or other records. Occasionally they learn the truth before the exaggerated headline arrives.

Continuity makes the duck feel real: it learns feeding schedules, prefers certain people, dislikes a delivery cart, and appears in places that make sense once the player understands the building.

One proposed recurring joke is a setting labeled **Enable duck-related notifications**. It starts enabled. Turning it off reveals additional duck notification settings.

## 16. Connections between stories

Possible intersections discussed:

- The previous employee built an unofficial duck-tracking dashboard.
- A promotion grants access to relevant old records.
- The hacker exploits a hastily installed duck livestream plugin.

Connections should enrich the shared workplace without forcing every event into one overarching conspiracy. The duck's behavior retains its grounded explanations.

## 17. Interface and pacing principles

- Make configuration, comparison, and experimentation satisfying.
- Provide useful information, clear previews, and generous undo options where appropriate.
- Reward opening new systems with meaningful decisions.
- Keep routine navigation efficient once a location has been discovered.
- Balance visible goals with obscure discoveries.
- Let automation reduce familiar work as the workspace expands.
- Deliver stories through the computer's ordinary interfaces.
- Preserve room for humor, curiosity, and occasional unease.

Opening many panels to perform a routine action is friction. Opening an overlooked panel and discovering a substantial new system is the desired reward.

## 18. Decisions still open

The concept does not yet establish:

- Target platforms, engine, or implementation stack.
- Visual style and exact desktop layout.
- Real versus fictional language and software names.
- Detailed currencies, resource costs, task durations, and balancing.
- Offline progress and how long-running processes behave while absent.
- Exact skill trees, plugin catalogs, project lists, and promotion ranks.
- Final characters, company identity, mystery answers, or endings.
- The full secret-menu map and specific unlock conditions.
- Whether there is a prestige/reset mechanic or any conventional victory condition.

## Concept statement

**Advanced Settings is a menu-driven incremental game about pretending to develop software at a strange company. Build programs, expand your tools, enlist AI help, earn promotions, defend against a hacker, investigate your predecessor's notes, and disappear into deeply hidden settings—while the media becomes increasingly convinced that an ordinary duck is doing extraordinary things.**
